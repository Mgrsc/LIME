# 原生引擎覆盖文件维护约束

## 固定上游基线

`app/src/main/cpp/cmake/librime.cmake` 固定 librime **1.17.0**，归档为
`app/src/main/cpp/Downloads/librime-1.17.0.tar.gz`，SHA-256：

```text
a60274da5d8b8a7187e6c7e9ba5023334ed7bdd182535e93c4e96de8cf188377
```

CMake 将 `app/src/main/cpp/src_override/rime/` 整体覆盖到解包源码树。
这些文件属于派生上游源码，不会随上游升级自动合并。升级版本时必须先逐文件
比较新上游，再重放本地差异；不能仅修改版本号并继续覆盖旧头文件。

## 组合代次与预算

`Composition::Reset` 隐藏了非虚的 `Segmentation::Reset`。当前生产调用位于
`ConcreteEngine::Compose`，以 `Composition&` 调用，保证每次重组更新代次；
`ScriptTranslator::Query` 据此更新新增搜索预算。不得改成通过
`Segmentation&` 或 `Segmentation*` 调用组合对象的 `Reset`，否则会绕过代次更新。
上游调整重组入口、静态类型或 `Reset` 调用时，应同时检查这项约束。

用户词库与系统词库拥有独立查词预算；每个来源分别按剩余位置分配，扣除实际
使用量。份额耗尽可以停止新增组合搜索，完整词和原有保底路径继续保留。
这不代表旧保底查词已经具有完整的最坏耗时上界。

原有组句路径的 `max_homophones` 分别限制用户与系统来源，不能让先查的用户
条目占满整个跨度。词图按文字与完整读音去重，同一条目优先保留非模糊匹配，
再比较原有权重与 `quality_len`；不同读音独立保留。新增简拼搜索沿用各来源
原有容量与共享图预算，重复条目替换不额外消耗图名额。`max_homophones`
只计实际新加入词图的条目；跨来源重复项不会占用后续独立词条的名额。此处只修复准入，
不保证已有加性评分能选出符合上下文的字词。

## 确认意图与学习

`EnginePipeline` 的空格、默认确认和提交后插入文本传递
`explicitSelection = false`；候选点击传递 `true`，包括主动点击第一项。
Kotlin 与 JNI 的候选快照接口必须一并更新。签名变化后删除失效的基线规则，
新热路径通过设备基准生成，不用手工替换描述符模拟已测结果。
非九键方案的原生数字选词同样传递明确意图；九键数字仍作为输入编码。

`lime_learning_selection.h` 只在同步选择调用期间设置原生 Context 临时属性，
调用结束恢复原值。`ScriptTranslator` 通过原生 `select_notifier` 的前置连接，
在引擎可能同步提交前把意图记录到当前 Segment 标签；连接由
`scoped_connection` 管理。不能等到整句提交时用最后一次点击的属性推断所有
前缀，也不能把原生 `partial` 标签当成主动选择证据，因为默认确认也可分段。
重新确认会刷新当前段标签，取消、清组合和换方案由原生段生命周期清理。

生产入口仅明确选择以正提交学习；自动确认以零提交表示，
在 `ScriptTranslator::SaveCommitEntry` 入口直接跳过学习，不新增用户词、
增加明确次数或改变既有词的动态权重。入口判断也覆盖超过 `max_word_length`
后直接更新组件的分支，不能只在 `Memorize` 阻断。明确选择整句后的组件仍使用
原生零提交更新已有记录；`UserDictionary::UpdateEntry(..., 0)`
必须在记录不存在时直接返回。同组合复合词要求每一段
都有明确选择证据，避免默认前缀或后缀被另一段的点击升级成强词。独立提交仍
不跨次合词。沿用原生事务、撤销、删词与重学机制，不增加第二套学习数据库。

面板收尾与硬件标点保留已高亮候选的展示身份，使用非显式学习意图确认；
普通空格继续在 Actor 中确认当前首选。按键从已发布候选解析目标，点击继续传递
实际绑定对象；
候选点击和数字选择明确声明主动意图，核心选择接口不提供隐含的主动默认值。
临时属性的 `0` 表示明确的自动确认，不能再被非首项位置推翻；未声明意图且
`selected_index > 0` 时的纠正推断仅作原生兜底，当前生产入口不依赖它。
现有 host 探针的 `accept` 固定选择首项，`pick=` 显式声明主动意图，
不能作为该非首项兜底分支的回归依据。
JNI 的按键与候选选择入口都会声明 `0`／`1`，不会走这一推断分支；高亮非首项后
自动确认仍不学习。普通空格确认当前首选，面板收尾／硬件标点确认已高亮对象。

用户词条的原生 `UserDbValue` 文本增加可选 `a=1`，表示该词曾在缩写／混输
路径被主动选择。完整拼音选择仍学习完整读音偏好，但不自动获得缩写优先权；
原有条目缺省没有此标记。按当前方案的原生拼写图识别实际缩写，不用键串长度
推断双拼或九键。标记随原生事务撤销，删除时清除，原生导入／合并保留有效
记录的标记；已有提交次数、动态权重和数据继续保留，无需迁移或清库。
旧版程序重新打包词条会丢弃该未知字段，因此降级不保证保留新标记。
流内排序、主／补充流比较和下游去重必须采用同一学习资格，不能让系统同词
先输出后隐藏已经获得缩写资格的用户版本。

## 候选展示身份

JNI 快照携带单调 `candidateRevision`。输入、选段、删除、光标、选项、方案、
原生会话和页大小的变更使旧版本失效；专用纯翻页接口保留版本。
`CandidateListItem` 随展示数据携带会话、来源类型、版本和位置；Adapter 必须
传递实际绑定对象，不能在点击时读取最新引擎状态后拼装旧位置的身份。
Actor 在选择／删除及联想删除前校验身份，JNI 再校验原生版本。展开翻页保留
同一组合已有页的引用；中文和英文的展示列表与引用列表同步追加。
选项、方案、编辑器策略的变更在同一 Actor 任务内完成设置、读取权威快照、
重建候选与分页引用、发布；读取失败只发布无候选的未就绪状态。页大小当前
只在启动时设置，后续由策略初始化读取新快照。
候选选择和删除的空串表示成功但无提交，`null` 表示拒绝；默认确认被拒绝时
只刷新权威状态并放弃本次动作，不能继续提交原始拼音、标点或移光标。
删除菜单的可删类型查询也通过 Actor 串行执行，避免后台读取正在更新的映射。
联想使用独立来源和递增版本，删除后更新版本并取消旧预测请求。

## 评分与顺序

无模型路径沿用上游 `Grammar::Evaluate` 的每词加性成本。设该成本为 `P`：
整词分数为 `w + P`，多词句分数为各组件分数之和；新增句的质量值为
`exp(score - P) + initial_quality`。该变换保持分数顺序，不按词数平均。
`SentenceScoreToQuality` 从上游零权重评分取得基础成本，不复制惩罚常数。

候选跨度、学习优先级、完整拼写及旧组句首项保护仍属于另外的定序规则。
原整词质量中的 `quality_len / full_code_length` 也予以保留；质量值不是所有
候选之间唯一的比较依据。本轮不声称已建立新的语言质量评分模型。

## 组句输出配置

简拼新增搜索同样受 `max_sentences` 与 `sentence_cutoff_threshold` 约束。
内部搜索容量不等于输出数量；保留的旧组句首项也占一个输出名额，重复文字
不重复占用名额。数量上限按单个 `ScriptTranslation` 生效，主／补充翻译
分别执行；`MergedTranslation` 未施加整个菜单的组句总上限。不能把单条输入
实测未超限，当作任意图与配置下的全局上限保证。

相对截断比较当前分数与已接纳的前一条组句：仅当
`last_weight - weight > cutoff_threshold * abs(last_weight)` 时停止，
每次接纳后沿用 `Poet::MakeSentences` 的阈值收紧比例。旧组句首项存在时
从该首项开始比较；其分数可能低于新搜索首项，不能用绝对差截掉更优的新句。
候选及比较起点按分数降序排列时，这个单向判据与 Poet 的相对下降规则等价。

上游 `TranslatorOptions` 将 `max_sentences` 归一到 1–100，未配置时为 1。
关闭组句使用 `enable_sentence: false`，不能把 `max_sentences: 0` 当作关闭。
配置回归中的 `max_sentences: 0` 因此必须按一条检查，关闭组句另有独立用例。
搜索回归中需要验证多句召回时，应在隔离方案中显式配置多句上限，不能依赖
搜索绕过生产默认值。默认上限生效后，先前依赖大量新增组句的尾部召回数据
不再适用于当前实现；改变默认数量需另行比较质量与成本。

## 配套验证入口

```sh
python3 tools/check_sentence_search.py --librime-build <host-build> --sanitize
python3 tools/dictionary/check_learning.py --probe <engine-probe>
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:assembleDebugAndroidTest --offline --console=plain
```

原生学习回归使用临时用户目录，检查独立提交不生成合并用户词、同组合学习及
重启保留，并覆盖默认／明确确认、分段混合意图、撤销／取消、删词重学、
禁止学习和全拼／双拼／九键。`check_preedit_mapping.py` 使用实际 Debug Kotlin
类与生产 JNI，注册并调用候选快照方法，核对布尔参数与三方案学习行为。
可传 `--actor-classpath <coroutines-core-jar>:<gradle-android-stubs-jar>`，运行
真实 Actor 的选项同步、选择、拒绝恢复和快照失败场景；该联调不等同于设备测试。
Android 候选快照不公开候选类型，因此设备测试只验证独立 T9 提交，
不以“候选文字出现”推断用户词库写入。构建测试 APK 不能替代设备执行。

`--sanitize` 将生产 `sentence_search.cc` 直接编入 ASan／UBSan 单测，覆盖搜索
与输出限制；同次运行中的实际引擎集成测试链接普通宿主库，不代表整个引擎
均已插桩。保留验证记录时应保存编译命令、运行命令和退出状态。

提交时应一并包含新增的搜索／预算头文件、实现文件及验证工具；未跟踪文件
不会自动进入提交。本记录不授权暂存、提交或推送。
